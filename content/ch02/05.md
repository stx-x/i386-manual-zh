# 2.5 操作数的选择

一条指令可以作用于零个或多个操作数，操作数就是指令所处理的数据。零操作数指令的例子是 `NOP`（无操作）。操作数可以位于以下任一位置：

- 指令自身之内（立即操作数）。
- 寄存器中（32 位操作数时为 EAX、EBX、ECX、EDX、ESI、EDI、ESP 或 EBP；16 位操作数时为 AX、BX、CX、DX、SI、DI、SP 或 BP；8 位操作数时为 AH、AL、BH、BL、CH、CL、DH 或 DL；也可以是段寄存器；标志操作中还可以是 EFLAGS 寄存器）。
- 内存中。
- I/O 端口中。

立即操作数和寄存器操作数比内存操作数访问得更快，因为内存操作数必须从存储器中取出。寄存器操作数就在 CPU 内；立即操作数也在 CPU 内，因为它们是作为指令的一部分被预取的。

在带操作数的指令中，有些隐式指定操作数，有些显式指定，还有些两者兼用。例如：

- **隐含操作数**：`AAM`。按定义，`AAM`（ASCII 乘法调整）对 AX 寄存器的内容进行操作。
- **显式操作数**：`XCHG EAX, EBX`。待交换的两个操作数编码在操作码之后的指令字节中。
- **隐式与显式操作数兼有**：`PUSH COUNTER`。内存变量 COUNTER（显式操作数）被复制到栈顶（隐含操作数）。

注意，大多数指令都有隐含操作数。例如所有算术指令都会更新 EFLAGS 寄存器。

一条 80386 指令可以显式引用一个或两个操作数。双操作数指令（如 `MOV`、`ADD`、`XOR` 等）通常用运算结果覆盖两个参与操作数中的一个。因此可以区分**源操作数**（不受操作影响的那个）和**目的操作数**（被结果覆盖的那个）。

对大多数指令而言，两个显式指定的操作数（源或目的）中有一个可以位于寄存器或内存中，另一个则必须是寄存器，或者必须是立即源操作数。因此，80386 的显式双操作数指令允许下列各类操作：

- 寄存器到寄存器
- 寄存器到内存
- 内存到寄存器
- 立即数到寄存器
- 立即数到内存

不过，某些串指令和栈操作指令会在内存与内存之间传送数据。某些串指令的两个操作数都在内存中，并且都是隐式指定的。压栈和出栈操作允许在内存操作数与位于内存中的栈之间传送数据。

## 2.5.1 立即操作数

某些指令把指令自身中的数据作为一个（有时是两个）操作数。这种操作数称为**立即操作数**。操作数的长度可以是 32 位、16 位或 8 位。例如：

```
SHR PATTERN, 2
```

指令的一个字节存放数值 2，即变量 PATTERN 需要移位的位数。

```
TEST PATTERN, 0FFFF00FFH
```

指令中的一个双字存放用于测试变量 PATTERN 的掩码。

## 2.5.2 寄存器操作数

操作数可以位于 32 位通用寄存器之一（EAX、EBX、ECX、EDX、ESI、EDI、ESP 或 EBP），也可以位于 16 位通用寄存器之一（AX、BX、CX、DX、SI、DI、SP 或 BP），或 8 位通用寄存器之一（AH、BH、CH、DH、AL、BL、CL 或 DL）。

80386 提供了用于引用段寄存器（CS、DS、ES、SS、FS、GS）的指令。只有当系统设计者选择了分段存储模型时，应用程序才会用到这些指令。

80386 还提供了引用标志寄存器的指令。标志可以存入栈中，也可以从栈中恢复。某些指令直接修改 EFLAGS 寄存器中常用的标志；另一些很少改动的标志，则可以通过栈中的标志映像间接修改。

## 2.5.3 内存操作数

在内存中寻址操作数的数据处理指令，必须（直接或间接地）指明含该操作数的段，以及该操作数在段内的偏移。不过，为了速度和紧凑的指令编码，段选择子存放在高速的段寄存器中。因此，数据处理指令只需指明所需的段寄存器和偏移，就能寻址一个内存操作数。

访问内存的 80386 数据处理指令，采用下列方法之一来指明内存操作数在其段内的偏移：

1. 大多数访问内存的数据处理指令都含有一个字节，用它显式指明操作数的寻址方法。这个字节称为 **modR/M 字节**，位于操作码之后，指明操作数是在寄存器中还是在内存中。若操作数在内存中，则地址由段寄存器与下列取值中的任意几项计算得出：基址寄存器、变址寄存器、比例因子、位移。使用变址寄存器时，modR/M 字节之后还会跟一个字节，用来标识变址寄存器和比例因子。这种寻址方法最为灵活。
2. 少数数据处理指令隐式使用专门的寻址方法：
   - 对于少数隐式使用 EAX 寄存器的 `MOV` 短格式，操作数的偏移以双字形式编码在指令中，不使用基址寄存器、变址寄存器或比例因子。
   - 串操作通过 DS:ESI（`MOVS`、`CMPS`、`OUTS`、`LODS`、`SCAS`）或 ES:EDI（`MOVS`、`CMPS`、`INS`、`STOS`）隐式寻址内存。
   - 栈操作通过 SS:ESP 寄存器隐式寻址操作数，例如 `PUSH`、`POP`、`PUSHA`、`PUSHAD`、`POPA`、`POPAD`、`PUSHF`、`PUSHFD`、`POPF`、`POPFD`、`CALL`、`RET`、`IRET`、`IRETD`，以及异常和中断。

### 2.5.3.1 段的选择

数据处理指令不必显式指明使用哪个段寄存器。对所有这些指令来说，段寄存器的指定都是可选的。对于所有内存访问，如果指令没有显式指定段，处理器就按表 2-1 的规则自动选择段寄存器。（如果系统设计者选择了平坦存储组织模型，那么段寄存器以及处理器据以选择段寄存器的规则，对应用程序来说都是感觉不到的。）

表 2-1　默认段寄存器选择规则

| 所需的内存引用 | 使用的段寄存器 | 隐含的段选择规则 |
|---|---|---|
| 指令 | 代码段（CS） | 取指令时自动选择 |
| 栈 | 堆栈段（SS） | 所有压栈和出栈操作；任何以 ESP 或 EBP 为基址寄存器的内存引用 |
| 局部数据 | 数据段（DS） | 除相对于栈或串目的之外的所有数据引用 |
| 目的串 | 附加段（ES） | 串指令的目的 |

内存引用的类型与该操作数所在的段之间存在密切的对应关系。一般来说，内存引用意味着使用当前数据段（即隐含的段选择子在 DS 中）。但 ESP 和 EBP 用于访问栈上的数据项，因此当 ESP 或 EBP 作为基址寄存器使用时，隐含的是当前栈段（即 SS 中含有选择子）。

可以使用专门的指令前缀要素来超越默认的段选择。段超越前缀允许显式选择段。80386 为每个段寄存器都提供了一个段超越前缀。只有在下列特殊情况下，隐含的段选择才无法被段前缀超越：

- 串指令中用作目的串的 ES。
- 栈指令中使用的 SS。
- 取指令时使用的 CS。

### 2.5.3.2 有效地址的计算

modR/M 字节提供了最灵活的寻址方法，而在 80386 指令集中，以 modR/M 字节作为指令第二个字节的指令最为常见。对于由 modR/M 定义的内存操作数，其在目标段内的偏移由至多三个部分相加得出：

- 指令中的位移部分。
- 基址寄存器。
- 变址寄存器。变址寄存器可以自动乘以 2、4 或 8 的比例因子。

这几部分相加得到的偏移称为**有效地址（effective address）**。有效地址的每个组成部分都可以取正值或负值。如果所有组成部分之和超过 2^(32)，有效地址会被截断为 32 位。图 2-10 展示了 modR/M 寻址的全部可能组合。

位移部分因为编码在指令中，适合表达寻址中固定不变的部分，例如：

- 简单标量操作数的位置。
- 静态分配的数组的起始位置。
- 记录中某一项的偏移。

基址和变址两部分功能相似：两者都使用同一组通用寄存器，都可以用于寻址中动态确定的部分，例如：

- 栈中过程参数和局部变量的位置。
- 同一记录类型的若干实例之一，或记录数组中某条记录的起始位置。
- 多维数组中某一维的起始位置。
- 动态分配的数组的起始位置。

通用寄存器用作基址或变址时，有以下区别：

- ESP 不能用作变址寄存器。
- 当 ESP 或 EBP 用作基址寄存器时，默认段是 SS 选中的段；其他所有情况下默认段是 DS。

当数组元素宽度为 2、4 或 8 字节这一常见情形时，比例因子可以高效地对数组做索引。变址寄存器的移位由处理器在计算地址时完成，没有性能损失，因而省去了一条单独的移位或乘法指令。

基址、变址和位移三部分可以任意组合，其中任何一部分都可以为空。只有在同时使用变址时，才能使用比例因子。每一种组合都适用于程序员在高级语言和汇编语言中常用的数据结构。下面列举若干地址组成部分组合的典型用途。

- **位移**：仅用位移表示操作数的偏移。这种组合用于直接寻址静态分配的标量操作数，可以使用 8 位、16 位或 32 位位移。
- **基址**：操作数的偏移间接地由某个通用寄存器给出，如同“基址”变量。
- **基址 + 位移**：寄存器与位移一起使用，有两种不同用途：
  1. 元素大小不是 2、4 或 8 字节时，对静态数组做索引。位移部分编码数组起始处的偏移，寄存器存放计算结果，即某个元素在数组内的偏移。
  2. 访问记录中的某一项。位移部分定位记录中的某一项，基址寄存器则在记录的若干实例中选定一个，从而为这一常见功能提供紧凑的编码。
- **（变址 × 比例）+ 位移**：元素大小为 2、4 或 8 字节时，这种组合可以高效地对静态数组做索引。位移给出数组的起始地址，变址寄存器存放所需数组元素的下标，处理器自动施加比例因子，把下标转换为索引。
- **基址 + 变址 + 位移**：两个寄存器一起使用，可以支持二维数组（位移确定数组的起始位置），也可以支持记录数组的若干实例之一（位移指明记录中的某一项）。
- **基址 +（变址 × 比例）+ 位移**：数组元素宽度为 2、4 或 8 字节时，这种组合可以高效地对二维数组做索引。

上面“基址 + 位移”这一组合还有一个重要特例：访问栈中过程活动记录里的参数。此时 EBP 是基址寄存器的最佳选择，因为当 EBP 用作基址寄存器时，处理器自动使用栈段寄存器（SS）来定位操作数，从而为这一常见功能提供紧凑的编码。
