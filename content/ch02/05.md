# 2.5 操作数的选择

一条指令可以作用于零个或多个操作数，操作数就是指令所处理的数据。零操作数指令的例子是 `NOP`（无操作）。操作数可以位于以下任何位置：

- 指令自身中（立即操作数）；
- 寄存器中（32 位操作数用 EAX、EBX、ECX、EDX、ESI、EDI、ESP、EBP；16 位用 AX、BX、CX、DX、SI、DI、SP、BP；8 位用 AH、AL、BH、BL、CH、CL、DH、DL；也可以是段寄存器，或用于标志操作的 EFLAGS 寄存器）；
- 内存中；
- I/O 端口中。

立即操作数和寄存器操作数的访问速度快于内存操作数，因为内存操作数必须从存储器取回。寄存器操作数就在 CPU 中；立即操作数也在 CPU 中，因为它们作为指令的一部分被预取。

在有操作数的指令中，有些隐含地指定操作数，有些显式指定，还有些两者兼用。例如：`AAM` 按定义对 AX 寄存器的内容操作，是隐含操作数；`XCHG EAX, EBX` 的待交换操作数在操作码之后编码，是显式操作数；`PUSH COUNTER` 把内存变量 COUNTER（显式操作数）复制到栈顶（隐含操作数）。注意，大多数指令都有隐含操作数，例如所有算术指令都会更新 EFLAGS 寄存器。

一条 80386 指令可以显式引用一个或两个操作数。双操作数指令（如 `MOV`、`ADD`、`XOR`）通常用结果覆盖两个参与操作数之一。因此可以区分**源操作数**（不受操作影响的那个）和**目的操作数**（被结果覆盖的那个）。

对大多数指令而言，两个显式指定的操作数——源或目的——之一可以位于寄存器或内存中；另一个必须是寄存器，或者是立即源操作数。因此，80386 的显式双操作数指令允许以下各类操作：

- 寄存器到寄存器
- 寄存器到内存
- 内存到寄存器
- 立即数到寄存器
- 立即数到内存

不过，某些串指令和栈操作指令会在内存与内存之间传送数据。某些串指令的两个操作数都在内存中，且为隐含指定。压栈和出栈操作允许在内存操作数与位于内存的栈之间传送数据。

## 2.5.1 立即操作数

某些指令把指令自身中的数据作为一个（有时是两个）操作数，这种操作数称为**立即操作数**。其长度可以是 32 位、16 位或 8 位。例如：

```
SHR PATTERN, 2
```

指令的一个字节存放数值 2，即变量 PATTERN 要移位的位数。

```
TEST PATTERN, 0FFFF00FFH
```

指令的一个双字存放用于测试变量 PATTERN 的掩码。

## 2.5.2 寄存器操作数

操作数可以位于 32 位通用寄存器之一（EAX、EBX、ECX、EDX、ESI、EDI、ESP、EBP），16 位通用寄存器之一（AX、BX、CX、DX、SI、DI、SP、BP），或 8 位通用寄存器之一（AH、BH、CH、DH、AL、BL、CL、DL）。

80386 有引用段寄存器（CS、DS、ES、SS、FS、GS）的指令。只有当系统设计者选择了分段存储模型时，应用程序才会使用这些指令。

80386 也有引用标志寄存器的指令。标志可以存入栈，也可以从栈恢复。某些指令直接修改 EFLAGS 中常用的标志；其他很少修改的标志，可以通过栈中的标志映像间接修改。

## 2.5.3 内存操作数

在内存中寻址操作数的数据操作指令，必须（直接或间接地）指明包含该操作数的段，以及操作数在段内的偏移。不过，为了速度和紧凑的指令编码，段选择子存放在高速段寄存器中。因此，数据操作指令只需指定所需的段寄存器和偏移，就能寻址内存操作数。

访问内存的 80386 数据操作指令，采用以下方法之一来指定内存操作数在其段内的偏移：

1. 大多数访问内存的数据操作指令都含有一个字节，显式说明操作数的寻址方法。这个字节称为 **modR/M 字节**，跟在操作码之后，指明操作数在寄存器中还是在内存中。若在内存中，地址由段寄存器及下列值中的任意组合算出：基址寄存器、变址寄存器、比例因子、位移。使用变址寄存器时，modR/M 字节之后还跟一个字节，用于标识变址寄存器和比例因子。这种寻址方法最灵活。
2. 少数数据操作指令隐含使用专门的寻址方法：
   - 少数 `MOV` 短格式隐含使用 EAX 寄存器，操作数的偏移作为双字编码在指令中，不使用基址寄存器、变址寄存器或比例因子。
   - 串操作通过 DS:ESI（`MOVS`、`CMPS`、`OUTS`、`LODS`、`SCAS`）或 ES:EDI（`MOVS`、`CMPS`、`INS`、`STOS`）隐含寻址内存。
   - 栈操作通过 SS:ESP 寄存器隐含寻址操作数，例如 `PUSH`、`POP`、`PUSHA`、`PUSHAD`、`POPA`、`POPAD`、`PUSHF`、`PUSHFD`、`POPF`、`POPFD`、`CALL`、`RET`、`IRET`、`IRETD`，以及异常和中断。

### 2.5.3.1 段的选择

数据操作指令不必显式指定使用哪个段寄存器。对所有这类指令而言，段寄存器的指定都是可选的。对于所有内存访问，如果指令没有显式指定段，处理器就按表 2-1 的规则自动选择段寄存器。（如果系统设计者选择了平坦存储组织模型，应用程序看不到段寄存器，也看不到处理器选择段寄存器的规则。）

内存引用的类型与操作数所在的段之间有密切联系。一般而言，内存引用意味着当前数据段（即隐含的段选择子在 DS 中）。但是，ESP 和 EBP 用于访问栈上的数据项；因此，当 ESP 或 EBP 用作基址寄存器时，隐含的是当前栈段（即 SS 中含有选择子）。

可以用专门的指令前缀元素来超越默认的段选择。段超越前缀允许显式选择段。80386 为每个段寄存器都提供了一个段超越前缀。只有在以下特殊情况下，隐含的段选择才无法被段前缀超越：

- 串指令中目的串使用 ES；
- 栈指令中使用 SS；
- 取指令时使用 CS。

| 所需的内存引用 | 使用的段 | 隐含的段选择规则 |
|---|---|---|
| 指令 | 代码段（CS） | 取指令时自动选择 |
| 栈 | 栈段（SS） | 所有压栈和出栈；任何以 ESP 或 EBP 为基址寄存器的内存引用 |
| 局部数据 | 数据段（DS） | 除相对于栈或串目的之外的所有数据引用 |
| 目的串 | 附加段（ES） | 串指令的目的 |

### 2.5.3.2 有效地址的计算

modR/M 字节提供了最灵活的寻址方法，而以 modR/M 字节作为指令第二个字节的指令，在 80386 指令集中最为常见。对于由 modR/M 定义的内存操作数，目标段内的偏移由最多三个分量相加得出：

- 指令中的位移分量；
- 基址寄存器；
- 变址寄存器。变址寄存器可以自动乘以 2、4 或 8 的比例因子。

这些分量相加得到的偏移称为**有效地址（effective address）**。有效地址的每个分量都可以为正或为负。若所有分量之和超过 2^(32)，有效地址被截断为 32 位。图 2-10 展示了 modR/M 寻址的全部可能组合。

位移分量由于编码在指令中，适合表示寻址中固定的部分，例如：

- 简单标量操作数的位置；
- 静态分配数组的起始位置；
- 记录中某一项的偏移。

基址分量和变址分量功能相似：两者都使用同一组通用寄存器，都可用于寻址中动态确定的部分，例如：

- 栈中过程参数和局部变量的位置；
- 同一记录类型的多次出现之一，或记录数组中的某条记录；
- 多维数组某一维的起点；
- 动态分配数组的起点。

通用寄存器作为基址或变址分量的用途有以下差别：

- ESP 不能用作变址寄存器。
- 当 ESP 或 EBP 用作基址寄存器时，默认段是由 SS 选中的段；其他所有情况下默认段是 DS。

比例因子便于对数组进行高效索引，适用于数组元素宽度为 2、4 或 8 字节的常见情形。处理器在计算地址时完成变址寄存器的移位，不损失性能，因而省去了一条单独的移位或乘法指令。

基址、变址和位移分量可以任意组合，其中任一分量都可以为空。只有当同时使用变址时，才能使用比例因子。每一种组合都对应高级语言和汇编语言程序员常用的数据结构。以下是各种地址分量组合的一些典型用途：

- **位移**：仅用位移表示操作数的偏移，用于直接寻址静态分配的标量操作数。可使用 8 位、16 位或 32 位位移。
- **基址**：操作数的偏移在一个通用寄存器中间接给出，用于“基址化”变量。
- **基址 + 位移**：寄存器与位移一起使用，有两种不同用途：
  1. 索引元素大小不是 2、4 或 8 字节的静态数组。位移分量编码数组起始偏移，寄存器保存用于确定数组内特定元素偏移的计算结果。
  2. 访问记录中的项。位移分量定位记录内的项，基址寄存器从记录的多次出现中选定一个，从而为这一常见功能提供紧凑编码。
  这一组合的一个重要特例，是访问栈中过程活动记录的参数。此时 EBP 是基址寄存器的最佳选择：当 EBP 用作基址寄存器时，处理器自动使用栈段寄存器（SS）定位操作数，从而为这一常见功能提供紧凑编码。
- **(变址 × 比例) + 位移**：当元素大小为 2、4 或 8 字节时，这种组合可以高效索引静态数组。位移给出数组起始地址，变址寄存器保存所需数组元素的下标，处理器通过比例因子自动把下标转换为索引。
- **基址 + 变址 + 位移**：两个寄存器一起使用，可支持二维数组（位移确定数组起点），或记录数组的多个实例之一（位移指明记录中的项）。
- **基址 + (变址 × 比例) + 位移**：当二维数组的元素宽度为 2、4 或 8 字节时，这种组合可以提供高效的索引。
