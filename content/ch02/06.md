# 2.6 中断与异常

80386 有两种打断程序执行的机制：

1. **异常（Exceptions）**是同步事件，是 CPU 对执行指令期间检测到的某些状况的响应。
2. **中断（Interrupts）**是异步事件，通常由需要处理的外部设备触发。

中断与异常的相同之处在于：两者都会让处理器暂时挂起当前程序，转去执行优先级更高的程序。两者的主要区别在于来源。异常总是可以通过用导致异常的程序和数据重新执行而重现；中断则通常与当前正在执行的程序无关。

应用程序员通常不必关心中断的处理。系统程序员所需的更多中断资料见第 9 章。不过，某些异常与应用程序员有关，许多操作系统也允许应用程序处理这些异常。然而，应用程序与 80386 异常机制之间的接口由操作系统本身定义。

表 2-2 列出了应用程序员可能关心的异常：

- 执行 `DIV` 或 `IDIV` 时除数为零，或商对目的操作数来说太大，会产生**除法错误异常**（第 3 章讨论 `DIV` 和 `IDIV`）。
- 若**调试异常**由陷阱标志（TF）引起，它可能被反映回应用程序。
- 执行 `INT 3` 指令会产生**断点异常**。某些调试器用这条指令在特定位置停止程序执行。
- 执行 `INTO` 指令且 OF（溢出）标志已置位时（此前某次算术运算置位了 OF），会产生**溢出异常**（第 3 章讨论 `INTO`）。
- 执行 `BOUND` 指令且被检查的数组下标超出数组界限时，会产生**界限检查异常**（第 3 章讨论 `BOUND`）。
- 某些应用可能用非法操作码来扩展指令集。此时，非法操作码异常提供了模拟该操作码的机会。
- 若程序含有协处理器指令，而系统中没有协处理器，就会发生“协处理器不可用”异常。
- 协处理器检测到非法操作时，会产生**协处理器错误**。

`INT` 指令每次执行都会产生一个中断；处理器把它当作异常处理。该中断的效果（以及所有其他异常的效果）由应用程序或系统软件（由系统程序员提供）提供的异常处理程序决定。`INT` 指令本身在第 3 章讨论；异常的完整说明见第 9 章。

| 向量号 | 说明 |
|---|---|
| 0 | 除法错误（Divide Error） |
| 1 | 调试异常（Debug Exceptions） |
| 2 | NMI 中断 |
| 3 | 断点（Breakpoint） |
| 4 | `INTO` 检测到溢出 |
| 5 | `BOUND` 超出范围 |
| 6 | 非法操作码（Invalid Opcode） |
| 7 | 协处理器不可用（Coprocessor Not Available） |
| 8 | 双重异常（Double Exception） |
| 9 | 协处理器段越界（Coprocessor Segment Overrun） |
| 10 | 非法任务状态段（Invalid Task State Segment） |
| 11 | 段不存在（Segment Not Present） |
| 12 | 栈错误（Stack Fault） |
| 13 | 通用保护（General Protection） |
| 14 | 页错误（Page Fault） |
| 15 | （保留） |
| 16 | 协处理器错误（Coprocessor Error） |
| 17–32 | （保留） |
