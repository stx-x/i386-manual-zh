# 2.6 中断与异常

80386 有两种打断程序执行的机制：

1. **异常（Exceptions）**是同步事件，是 CPU 对执行指令期间检测到的某些状况作出的响应。
2. **中断（Interrupts）**是异步事件，通常由需要处理的外部设备触发。

中断与异常的共同之处在于：两者都会使处理器暂时挂起当前正在执行的程序，转去执行优先级更高的程序。两类中断的主要区别在于它们的来源。异常总可以通过用当初引发异常的程序和数据重新执行而重现；中断则通常与当前正在执行的程序无关。

应用程序员通常不必关心中断的处理。系统程序员所需的更多中断资料见第 9 章。不过，某些异常与应用程序员有关，许多操作系统也给应用程序提供处理这些异常的机会。但应用程序与 80386 异常机制之间的接口，由操作系统本身定义。

表 2-2 列出了应用程序员可能关心的异常。

- 当 `DIV` 或 `IDIV` 指令的除数为零，或商对目的操作数来说过大时，会产生**除法错误异常**。（`DIV` 和 `IDIV` 的讨论见第 3 章。）
- **调试异常**若由陷阱标志（TF）引起，可能会被反映回应用程序。
- 执行 `INT 3` 指令会产生**断点异常**。某些调试器用这条指令在特定位置停止程序执行。
- 执行 `INTO` 指令且 OF（溢出）标志已置位时（此前某次算术运算置位了 OF），会产生**溢出异常**。（`INTO` 的讨论见第 3 章。）
- 执行 `BOUND` 指令且被检查的数组下标超出数组界限时，会产生**界限检查异常**。（`BOUND` 指令的讨论见第 3 章。）
- 某些应用可能用非法操作码来扩展指令集。这种情况下，非法操作码异常就提供了模拟该操作码的机会。
- 如果程序中含有协处理器指令，而系统中并没有协处理器，就会发生**“协处理器不可用”异常**。
- 协处理器检测到非法操作时，会产生**协处理器错误**。

`INT` 指令每次执行都会产生一个中断，处理器把这个中断当作异常处理。这个中断的效果（以及所有其他异常的效果），由应用程序提供的、或作为系统软件一部分（由系统程序员提供）的异常处理程序决定。`INT` 指令本身在第 3 章讨论；异常的更完整说明见第 9 章。
