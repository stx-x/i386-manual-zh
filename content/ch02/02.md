# 2.2 数据类型

字节、字和双字是基本数据类型（见图 2-2）。字节是从任意逻辑地址开始的 8 个连续位，位编号为 0 到 7，其中位 0 是最低有效位。

字是从任意字节地址开始的两个连续字节，因此包含 16 位。字的位编号为 0 到 15，位 0 是最低有效位。包含字中位 0 的那个字节称为**低字节**，包含位 15 的那个字节称为**高字节**。

字中的每个字节都有自己的地址，其中较小的那个地址就是该字的地址。处于这个较低地址的字节存放字的 8 个最低有效位，处于较高地址的字节存放 8 个最高有效位。

双字是从任意字节地址开始的两个连续字，因此包含 32 位。双字的位编号为 0 到 31，位 0 是最低有效位。包含双字中位 0 的那个字称为**低字**，包含位 31 的那个字称为**高字**。

双字中的每个字节也都有自己的地址，其中最小的地址就是该双字的地址。处于这个最低地址的字节存放双字的 8 个最低有效位，处于最高地址的字节存放 8 个最高有效位。图 2-3 说明了字和双字内部字节的排列方式。

要注意，字不必对齐在偶数地址上，双字也不必对齐在能被 4 整除的地址上。这样，数据结构（例如同时含有字节、字、双字成员的记录）可以获得最大的灵活性，存储利用率也最高。在采用 32 位总线的系统中，处理器与存储器之间实际的数据传送以双字为单位，并且从能被 4 整除的地址开始；不过，对于未对齐的字或双字请求，处理器会把它转换成存储器接口所能接受的一系列请求。这类未对齐的数据传送需要额外的存储周期，因而会降低性能。为了获得最高的性能，设计数据结构（包括栈）时应尽量做到：字操作数对齐在偶数地址上，双字操作数对齐在能被 4 整除的地址上。由于 CPU 内部有指令预取和指令队列，指令本身不要求对齐在字或双字边界上。（不过，如果控制转移的目标地址能被 4 整除，速度会略有提高。）

字节、字和双字是基本的操作数类型，但处理器还支持对这些操作数作其他解释。视引用该操作数的指令而定，处理器还能识别下列数据类型：

| 类型 | 含义 |
|---|---|
| **整数（Integer）** | 存放在 32 位双字、16 位字或 8 位字节中的有符号二进制数。所有运算都按 2 的补码表示进行。符号位在字节中位于位 7，在字中位于位 15，在双字中位于位 31；正整数符号位为 0，负整数为 1。由于最高位被用作符号位，8 位整数的范围是 −128 至 +127，16 位整数是 −32,768 至 +32,767，32 位整数是 −2^(31) 至 +2^(31)−1。数值 0 的符号为正。 |
| **序数（Ordinal）** | 存放在 32 位双字、16 位字或 8 位字节中的无符号二进制数。所有位都参与确定数值的大小。8 位序数的取值范围是 0–255，16 位可以表示 0 至 65,535，32 位可以表示 0 至 2^(32)−1。 |
| **近指针（Near Pointer）** | 一个 32 位逻辑地址，即段内的偏移。平坦模型和分段模型都使用近指针。 |
| **远指针（Far Pointer）** | 由两部分组成的 48 位逻辑地址：16 位段选择子和 32 位偏移。只有当系统设计者选择了分段存储组织时，应用程序员才会用到远指针。 |
| **串（String）** | 连续的字节、字或双字序列。一个串可以包含 0 至 2^(32)−1 个字节（4 GB）。 |
| **位域（Bit field）** | 一段连续的位，可以从任意字节的任意位开始，最多包含 32 位。 |
| **位串（Bit string）** | 一段连续的位，可以从任意字节的任意位开始，最多包含 2^(32)−1 位。 |
| **BCD** | 十进制数字 0 至 9 的（非压缩）字节表示。非压缩十进制数以无符号字节量存放，每个字节存一位数字。数值大小由低半字节确定；十六进制值 0–9 有效，并被解释为十进制数字。做乘法和除法时，高半字节必须为 0；做加法和减法时，高半字节可以是任意值。 |
| **压缩 BCD（Packed BCD）** | 两个十进制数字（各在 0 至 9 之间）的（压缩）字节表示。每个半字节存一位数字，高半字节中的数字是最高位。两个半字节中 0–9 均为有效值。一个压缩十进制字节的取值范围是 0–99。 |
