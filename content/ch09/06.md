# 9.6 中断任务与中断过程

正如 `CALL` 指令既可以调用过程也可以调用任务，中断或异常也可以“调用”一个过程形式或任务形式的中断处理程序。响应中断或异常时，处理器用中断或异常标识号索引 IDT 中的描述符。若索引到中断门或陷阱门，就以类似于 `CALL` 调用门的方式调用处理程序；若找到任务门，就以类似于 `CALL` 调用任务门的方式引发任务切换。

## 9.6.1 中断过程

中断门或陷阱门间接指向一个过程，该过程在当前执行任务的上下文中运行，如图 9-4 所示。门的选择子指向 GDT 或当前 LDT 中的可执行段描述符；门的偏移字段指向中断或异常处理过程的起点。

80386 调用中断或异常处理过程的方式与 `CALL` 调用过程大致相同，区别在下面几节说明。

![图 9-4　中断门或陷阱门间接指向中断过程](fig9-4.gif)

### 9.6.1.1 中断过程的栈

与 `CALL` 指令引起的控制转移一样，转移到中断或异常处理过程时，也要用栈保存返回原过程所需的信息。如图 9-5 所示，中断先把 EFLAGS 寄存器压栈，再把指向被中断指令的指针压栈。

某些类型的异常还会把错误码压入栈。异常处理程序可以利用错误码帮助诊断异常。

### 9.6.1.2 从中断过程返回

中断过程离开过程的方式也与普通过程不同：用 `IRET` 指令退出中断过程。`IRET` 与 `RET` 类似，区别在于 `IRET` 让 ESP 额外增加 4 字节（因为栈上有标志），并把保存的标志移入 EFLAGS 寄存器。只有当 CPL 为零时，EFLAGS 的 IOPL 字段才会改变；只有当 CPL ≤ IOPL 时，IF 标志才会改变。

![图 9-5　中断过程压入栈的内容](fig9-5.gif)

### 9.6.1.3 中断过程对标志的使用

通过中断门或陷阱门向量的中断，会把 TF（陷阱标志）的当前值作为 EFLAGS 的一部分保存到栈上，然后复位 TF。处理器通过这一动作，防止使用单步执行的调试活动影响中断响应。随后的 `IRET` 指令把 TF 恢复为栈上 EFLAGS 映像中的值。

中断门与陷阱门的区别在于对 IF（中断允许标志）的影响。通过中断门向量的中断会复位 IF，从而防止其他中断干扰当前中断处理程序；随后的 `IRET` 把 IF 恢复为栈上 EFLAGS 映像中的值。通过陷阱门的中断不改变 IF。

### 9.6.1.4 中断过程中的保护

约束中断过程的特权规则与过程调用类似：CPU 不允许中断把控制转移给特权级更低（数值上大于当前特权级）的段中的过程。违反该规则的企图会导致通用保护异常。

由于中断的发生通常不可预测，这条特权规则实际上限制了中断和异常处理过程可以执行的特权级。可以采用以下任一策略确保永不违反该规则：

- **把处理程序放在一致段中**。该策略适合某些异常（如除法错误）的处理程序。此类处理程序只能使用栈上可用的数据；若它需要数据段中的数据，该数据段就必须是特权级 3，从而失去保护。
- **把处理过程放在特权级 0 的段中**。

## 9.6.2 中断任务

IDT 中的任务门间接指向一个任务，如图 9-6 所示。门的选择子指向 GDT 中的 TSS 描述符。

当中断或异常的向量指向 IDT 中的任务门时，会产生任务切换。用独立任务处理中断有两个优点：

- 整个上下文被自动保存；
- 可以通过给中断处理程序独立的地址空间（通过其 LDT 或页目录）把它与其他任务隔离。

处理器执行任务切换的动作见第 7 章。中断任务通过执行 `IRET` 指令返回被中断的任务。

若任务切换由带错误码的异常引起，处理器自动把错误码压入与中断任务中第一条待执行指令特权级相对应的栈。

在 80386 操作系统中使用中断任务时，实际上有两个调度器：软件调度器（操作系统的一部分）和硬件调度器（处理器中断机制的一部分）。软件调度器的设计应考虑到：只要中断允许，硬件调度器就可能调度一个中断任务。
