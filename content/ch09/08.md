# 9.8 异常条件

以下各节详细描述每一种可能的异常条件。每种描述都把异常归类为故障、陷阱或中止，这一分类为系统程序员重新执行发生异常的过程提供了所需信息。

**故障**：报告故障时保存的 CS 和 EIP 值指向导致故障的指令。

**陷阱**：报告陷阱时保存的 CS 和 EIP 值指向导致陷阱的指令之后动态执行的那条指令。若陷阱是在改变程序流程的指令执行期间检测到的，报告的 CS 和 EIP 值反映改变后的流程。例如，若在 `JMP` 指令中检测到陷阱，压栈的 CS 和 EIP 值指向 `JMP` 的目标，而不是 `JMP` 之后的那条指令。

**中止**：既不精确定位导致异常的指令，也不允许重新执行导致异常的程序。中止用于报告严重错误，如硬件错误以及系统表中不一致或非法的值。

## 9.8.1 中断 0——除法错误

当 `DIV` 或 `IDIV` 指令的除数为零时，发生除法错误故障。

## 9.8.2 中断 1——调试异常

处理器在多种条件下触发该中断，异常是故障还是陷阱取决于具体条件：

- 指令地址断点故障；
- 数据地址断点陷阱；
- 通用检测故障；
- 单步陷阱；
- 任务切换断点陷阱。

处理器不为该异常压入错误码。异常处理程序可以检查调试寄存器，判断是哪种条件引发了异常。调试和调试寄存器的详细信息见第 12 章。

## 9.8.3 中断 3——断点

`INT 3` 指令引发该陷阱。`INT 3` 只有一个字节长，因此很容易用断点操作码替换可执行段中的某个操作码。操作系统或调试子系统可以利用可执行段的数据段别名，在方便的位置放置 `INT 3`，以便中止正常执行并进行特殊处理。调试器通常用断点在任务的关键位置显示寄存器、变量等。

保存的 CS:EIP 值指向断点之后的字节。若调试器用有效操作码替换了植入的断点，返回前必须把保存的 EIP 值减一。调试的更多信息见第 12 章。

## 9.8.4 中断 4——溢出

当处理器遇到 `INTO` 指令且 OF（溢出）标志已置位时，发生该陷阱。由于有符号算术和无符号算术使用相同的算术指令，处理器无法判断程序员意图，因此不会自动产生溢出异常；它只在结果按有符号数解释会超出范围时置位 OF。对有符号操作数进行运算时，谨慎的程序员和编译器会直接测试 OF，或使用 `INTO` 指令。

## 9.8.5 中断 5——界限检查

当处理器执行 `BOUND` 指令时发现操作数超出规定界限，发生该故障。程序可以用 `BOUND` 指令，把有符号数组下标与内存块中定义的有符号界限比较。

## 9.8.6 中断 6——非法操作码

当执行单元检测到非法操作码时，发生该故障。（只有试图执行非法操作码时才会检测到异常；预取非法操作码不会引发该异常。）不压入错误码，异常可以在同一任务内处理。

当操作数类型对给定操作码非法时，也会发生该异常。例如，段间 `JMP` 引用寄存器操作数，或 `LES` 指令的源操作数是寄存器。

## 9.8.7 中断 7——协处理器不可用

该异常在以下任一条件下发生：

- 处理器遇到 `ESC`（转义）指令，且 CR0（控制寄存器零）的 EM（模拟）位置位；
- 处理器遇到 `WAIT` 指令或 `ESC` 指令，且 CR0 的 MP（监视协处理器）位与 TS（任务已切换）位都置位。

协处理器接口的信息见第 11 章。

## 9.8.8 中断 8——双重故障

通常，当处理器在试图调用前一个异常的处理程序时又检测到异常，这两个异常可以串行处理。但若处理器无法串行处理它们，就发出双重故障异常。为判断两个故障何时应作为双重故障发出，80386 把异常分为三类：良性异常、贡献性异常和页错误。表 9-3 给出这一分类，表 9-4 给出哪些异常组合导致双重故障。

处理器总是把错误码压入双重故障处理程序的栈，但该错误码总是零。导致故障的指令不能重新执行。若在试图调用双重故障处理程序时又发生任何其他异常，处理器关闭（shutdown）。

## 9.8.9 中断 9——协处理器段越界

在保护模式下，若 80386 在把协处理器操作数的中间部分传送给 NPX 时检测到页违规或段违规，就产生该异常。该异常可以避免。协处理器接口的更多信息见第 11 章。

## 9.8.10 中断 10——非法 TSS

若任务切换期间新 TSS 非法，发生中断 10。表 9-5 列出了 TSS 被视为非法的情况。处理器压入错误码以帮助确定故障原因；EXT 位指示异常是否由程序无法控制的条件引起，例如通过任务门的外部中断触发了切换到非法 TSS。

该故障可能发生在原任务的上下文中，也可能发生在新任务的上下文中。在处理器完全验证新 TSS 存在之前，异常发生在原任务上下文中。一旦确认新 TSS 存在，任务切换即被视为完成：TR 已更新，且若切换由 `CALL` 或中断引起，新 TSS 的回链已设为旧 TSS。此后处理器发现的任何错误都在新任务上下文中处理。

为确保有合适的 TSS 来处理该异常，异常 10 的处理程序必须是通过任务门调用的任务。

| 错误码 | 条件 |
|---|---|
| TSS id + EXT | TSS 描述符中的界限小于 103 |
| LDT id + EXT | 非法 LDT 选择子，或 LDT 不存在 |
| SS id + EXT | 栈段选择子超出表界限 |
| SS id + EXT | 栈段不是可写段 |
| SS id + EXT | 栈段 DPL 与新 CPL 不匹配 |
| SS id + EXT | 栈段选择子 RPL ≠ CPL |
| CS id + EXT | 代码段选择子超出表界限 |
| CS id + EXT | 代码段选择子未引用代码段 |
| CS id + EXT | 非一致代码段的 DPL ≠ 新 CPL |
| CS id + EXT | 一致代码段的 DPL > 新 CPL |
| DS/ES/FS/GS id + EXT | DS、ES、FS 或 GS 段选择子超出表界限 |
| DS/ES/FS/GS id + EXT | DS、ES、FS 或 GS 不是可读段 |

## 9.8.11 中断 11——段不存在

当处理器检测到描述符的存在位为零时，发生异常 11。处理器可在以下任一情况下触发该故障：

- 试图装入 CS、DS、ES、FS 或 GS 寄存器时；不过，装入 SS 寄存器会导致栈错误；
- 试图用 `LLDT` 指令装入 LDT 寄存器时；不过，在任务切换操作期间装入 LDT 寄存器会导致“非法 TSS”异常；
- 试图使用标记为不存在的门描述符时。

该故障可以重新执行。若异常处理程序使段存在并返回，被中断的程序将继续执行。

若任务切换期间发生段不存在异常，任务切换的各步骤并未全部完成。任务切换期间，处理器先装入所有段寄存器，再检查其内容是否有效。若发现段不存在异常，其余段寄存器尚未检查，因此可能无法用于引用内存。段不存在异常处理程序不应指望在不引发另一个异常的情况下使用 CS、SS、DS、ES、FS、GS 中的值。处理程序应在试图恢复新任务之前检查所有段寄存器，否则以后可能在更难诊断的条件下产生通用保护错误。有三种方法处理这种情况：

1. 用任务处理段不存在故障。切回被中断任务时，处理器会从 TSS 装入寄存器并检查它们。
2. 对所有段寄存器执行 `PUSH` 和 `POP`。每次 `POP` 都会让处理器检查段寄存器的新内容。
3. 仔细检查 TSS 中每个段寄存器映像的内容，模拟处理器装入段寄存器时所做的测试。

该异常把错误码压入栈。若程序外部的事件引起中断，而该中断随后引用了不存在的段，则错误码的 EXT 位置位。若错误码引用 IDT 表项（例如 `INT` 指令引用了不存在的门），则 I 位置位。

操作系统通常用“段不存在”异常在段一级实现虚拟存储器。不过，门描述符中的不存在指示通常并不表示段不存在（因为门不一定对应段）。操作系统可以用不存在的门触发对操作系统有特殊意义的异常。

## 9.8.12 中断 12——栈异常

栈错误在以下两种一般条件下发生：

- 任何引用 SS 寄存器的操作发生界限违规。这包括面向栈的指令（如 `POP`、`PUSH`、`ENTER`、`LEAVE`），以及隐式使用 SS 的其他内存引用（例如 `MOV AX, [BP+6]`）。当栈太小、容纳不下指定的局部变量空间时，`ENTER` 会引发该异常。
- 试图用标记为不存在、但在其他方面有效的描述符装入 SS 寄存器。这可能发生在任务切换、跨级 `CALL`、跨级返回、`LSS` 指令，或对 SS 的 `MOV`/`POP` 指令中。

处理器检测到栈异常时，把错误码压入异常处理程序的栈。若异常由栈段不存在、或跨级 `CALL` 期间新栈溢出引起，错误码含有相关段的选择子（处理程序可以测试描述符中的存在位来判断是哪种异常）；否则错误码为零。

导致该故障的指令在所有情况下都可以重新执行。压入异常处理程序栈的返回指针指向需要重新执行的指令。该指令通常是导致异常的那条；不过，若栈异常由任务切换期间装入不存在的栈段描述符引起，所指指令是新任务的第一条指令。

任务切换期间发生栈错误时，段寄存器可能无法用于引用内存。任务切换期间，选择子值在描述符检查之前装入。若发现栈错误，其余段寄存器尚未检查，因此可能无法用于引用内存。栈错误处理程序不应指望在不引发另一个异常的情况下使用 CS、SS、DS、ES、FS、GS 中的值。处理程序应在试图恢复新任务之前检查所有段寄存器，否则以后可能在更难诊断的条件下产生通用保护错误。

## 9.8.13 中断 13——通用保护异常

所有不导致其他异常的保护违规都会导致通用保护异常，包括（但不限于）：

1. 使用 CS、DS、ES、FS 或 GS 时超出段界限；
2. 引用描述符表时超出段界限；
3. 把控制转移到不可执行段；
4. 写入只读数据段或代码段；
5. 从只执行段读取；
6. 用只读描述符装入 SS（若选择子来自任务切换期间的 TSS，则发生 TSS 异常）；
7. 用系统段描述符装入 SS、DS、ES、FS 或 GS；
8. 用不可读的可执行段描述符装入 DS、ES、FS 或 GS；
9. 用可执行段描述符装入 SS；
10. 当段寄存器含空选择子时，通过 DS、ES、FS 或 GS 访问内存；
11. 切换到忙任务；
12. 违反特权规则；
13. 用 PG=1、PE=0 装入 CR0；
14. 从 V86 模式经陷阱门或中断门中断/异常到非零特权级；
15. 超过 15 字节的指令长度限制（只有指令前放置了冗余前缀时才可能发生）。

通用保护异常是故障。处理器把错误码压入异常处理程序的栈。若装入描述符导致异常，错误码含有该描述符的选择子；否则错误码为空。错误码中选择子的来源可能是：

1. 指令的操作数；
2. 作为指令操作数的门中的选择子；
3. 任务切换所涉及 TSS 中的选择子。

## 9.8.14 中断 14——页错误

当分页启用（PG=1），且处理器在把线性地址转换为物理地址时检测到以下情况之一，发生该异常：

- 地址转换所需的页目录项或页表项的存在位为零；
- 当前过程没有足够特权访问指定页。

处理器向页错误处理程序提供两项信息，帮助诊断异常并恢复：

- **栈上的错误码**。页错误错误码的格式与其他异常不同（见图 9-8），它告诉处理程序三件事：异常是由页不存在还是访问权违规引起；异常发生时处理器在用户级还是超级用户级执行；导致异常的内存访问是读还是写。
- **CR2（控制寄存器二）**。处理器把导致异常的访问所用线性地址存入 CR2（见图 9-9）。处理程序可以用该地址定位相应的页目录项和页表项。若页错误处理程序执行期间可能发生另一次页错误，处理程序应把 CR2 压栈。

### 9.8.14.1 任务切换期间的页错误

任务切换期间，处理器可能访问以下四个段：

1. 把原任务的状态写入该任务的 TSS；
2. 读取 GDT，以定位新任务的 TSS 描述符；
3. 读取新任务的 TSS，以检查其中段描述符的类型；
4. 可能读取新任务的 LDT，以验证新 TSS 中保存的段寄存器。

访问这些段中的任何一个都可能产生页错误。后两种情况下异常发生在新任务上下文中，指令指针指向新任务的下一条指令，而不是导致任务切换的指令。若操作系统的设计允许任务切换期间发生页错误，页错误处理程序应通过任务门调用。

### 9.8.14.2 栈指针不一致时的页错误

应特别小心，确保页错误不会使处理器使用无效的栈指针（SS:ESP）。为 8086 系列早期处理器编写的软件，常用一对指令切换到新栈，例如：

```
MOV SS, AX
MOV SP, StackTop
```

在 80386 上，由于第二条指令访问内存，可能在 SS 已改变、SP 尚未相应改变时发生页错误。此时栈指针 SS:SP（32 位程序中为 SS:ESP）的两部分不一致。

若页错误的处理导致切换到定义良好的栈（即处理程序是任务或特权更高的过程），处理器不会使用不一致的栈指针。不过，若页错误处理程序由陷阱门或中断门调用，且页错误发生在与处理程序相同的特权级，处理器将试图使用当前（无效）栈指针所指示的栈。

在实现分页并在故障任务内处理页错误（用陷阱门或中断门）的系统中，与页错误处理程序同特权级执行的软件应使用新的 `LSS` 指令初始化新栈，而不是上面那对指令。当页错误处理程序在特权级 0 执行时（通常情况），问题范围仅限于特权级 0 代码，通常就是操作系统内核。

## 9.8.15 中断 16——协处理器错误

当 80386 在 ERROR# 输入引脚上检测到 80287 或 80387 的信号时，报告该异常。80386 只在一定 `ESC` 指令开始时，以及在 MSW 的 EM 位为零（不模拟）时遇到 `WAIT` 指令时，才测试该引脚。协处理器接口的更多信息见第 11 章。
