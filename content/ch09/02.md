# 9.2 允许与禁止中断

处理器只在一条指令结束之后、下一条指令开始之前处理中断和异常。使用重复前缀重复串指令时，中断和异常可以在两次重复之间发生，因此对长串的操作不会延迟中断响应。

某些条件和标志设置会使处理器在指令边界处禁止某些中断和异常。

## 9.2.1 NMI 屏蔽后续 NMI

NMI 处理程序执行期间，处理器忽略 NMI 引脚上的后续中断信号，直到执行下一条 `IRET` 指令。

## 9.2.2 IF 屏蔽 INTR

IF（中断允许标志）控制是否接受通过 INTR 引脚发出的外部中断。IF=0 时禁止 INTR 中断，IF=1 时允许。与其他标志位一样，处理器在响应 RESET 信号时清零 IF。`CLI` 和 `STI` 指令改变 IF 的设置。

`CLI`（清中断允许标志）和 `STI`（置中断允许标志）显式改变 IF（标志寄存器中的位 9）。这两条指令只能在 CPL ≤ IOPL 时执行。

IF 还会被以下操作隐式影响：

- `PUSHF` 指令把所有标志（包括 IF）存入栈中，以便检查；
- 任务切换以及 `POPF`、`IRET` 指令装入标志寄存器，因此可用于修改 IF；
- 通过中断门的中断自动复位 IF，从而禁止中断（中断门将在本章后面解释）。

## 9.2.3 RF 屏蔽调试故障

EFLAGS 中的 RF 位控制调试故障的识别。这使得对给定指令最多只能引发一次调试故障，无论该指令被重新执行多少次（调试的更多信息见第 12 章）。

## 9.2.4 对 SS 的 MOV 或 POP 屏蔽部分中断与异常

需要改变栈段的软件常使用一对指令，例如：

```
MOV SS, AX
MOV ESP, StackTop
```

若在 SS 已改变、ESP 尚未相应改变时处理中断或异常，栈指针 SS:ESP 的两部分在中断或异常处理程序执行期间将不一致。

为防止这种情况，80386 在 `MOV SS` 和 `POP SS` 指令之后，于改变 SS 的那条指令之后的指令边界处禁止 NMI、INTR、调试异常和单步陷阱。某些异常仍可能发生，即页错误和通用保护错误。始终使用 80386 的 `LSS` 指令，就不会出现这个问题。
