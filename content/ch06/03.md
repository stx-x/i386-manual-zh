# 6.3 段级保护

保护的五个方面都适用于段转换：

1. 类型检查；
2. 界限检查；
3. 可寻址范围的限制；
4. 过程入口点的限制；
5. 指令集的限制。

段是保护的单位，段描述符存放保护参数。当段描述符的选择子被装入段寄存器时，以及每次访问段时，CPU 自动执行保护检查。段寄存器保存当前可寻址段的保护参数。

## 6.3.1 描述符存放保护参数

图 6-1 突出显示了段描述符中与保护有关的字段。保护参数由系统软件在创建描述符时放入描述符；一般来说，应用程序员不必关心保护参数。

当程序把选择子装入段寄存器时，处理器不仅装入段的基地址，还装入保护信息。每个段寄存器的不可见部分都有用于存放基址、界限、类型和特权级的位；因此，对同一段的后续保护检查不会占用额外时钟周期。

### 6.3.1.1 类型检查

描述符的 TYPE 字段有两个作用：

1. 区分不同的描述符格式；
2. 规定段的预期用途。

除了应用程序常用的数据段和可执行段描述符之外，80386 还有供操作系统使用的特殊段描述符以及门描述符。表 6-1 列出了为系统段和门定义的所有类型。注意，并非所有描述符都定义段；门描述符的用途不同，将在本章后面讨论。

数据段和可执行段描述符的类型字段还含有进一步规定段用途的位（见图 6-1）：

- 数据段描述符中的**可写位**规定指令能否写入该段；
- 可执行段描述符中的**可读位**规定指令能否从该段读取（例如读取与指令存放在一起的常数）。可读的可执行段可以通过两种方式读取：
  - 通过 CS 寄存器，使用 CS 超越前缀；
  - 把该描述符的选择子装入数据段寄存器（DS、ES、FS 或 GS）。

类型检查可用于发现那些试图以程序员非预期方式使用段的编程错误。处理器在两种场合检查类型信息：

1. 当描述符的选择子被装入段寄存器时。某些段寄存器只能容纳某些描述符类型，例如：
   - CS 只能装入可执行段的选择子；
   - 不可读的可执行段选择子不能装入数据段寄存器；
   - SS 只能装入可写数据段的选择子。
2. 当指令（隐式或显式）引用段寄存器时。某些段只能以预先规定的方式被指令使用，例如：
   - 任何指令都不能写入可执行段；
   - 若数据段的可写位未置位，任何指令都不能写入该段；
   - 除非可读位置位，任何指令都不能读取可执行段。

|---|---|
| 0 | 保留 |
| 1 | 可用的 286 TSS |
| 2 | LDT |
| 3 | 忙的 286 TSS |
| 4 | 调用门 |
| 5 | 任务门 |
| 6 | 286 中断门 |
| 7 | 286 陷阱门 |
| 8 | 保留 |
| 9 | 可用的 386 TSS |
| A | 保留 |
| B | 忙的 386 TSS |
| C | 386 调用门 |
| D | 保留 |
| E | 386 中断门 |
| F | 386 陷阱门 |

### 6.3.1.2 界限检查

处理器用段描述符的界限字段防止程序寻址到段外。处理器对界限的解释取决于 G（粒度）位的设置。对于数据段，解释还取决于 E 位（扩展方向位）和 B 位（大位），见表 6-2。

当 G=0 时，实际界限就是描述符中 20 位界限字段的值，范围为 0 到 0FFFFFH（2^(20)−1，即 1 MB）。当 G=1 时，处理器在界限字段值后附加 12 个低位 1，实际界限范围为 0FFFH（2^(12)−1，即 4 KB）到 0FFFFFFFFH（2^(32)−1，即 4 GB）。

对于除向下扩展数据段以外的所有段类型，界限值等于段长度（以字节计）减一。出现以下任一情况时，处理器产生通用保护异常：

- 试图访问地址 > 界限的内存字节；
- 试图访问地址 ≥ 界限的内存字；
- 试图访问地址 ≥ (界限−2) 的内存双字。

对于向下扩展数据段，界限的作用相同，但解释方式不同：有效地址范围是从界限+1 到 64K 或 2^(32)−1（4 GB），取决于 B 位。界限为零时，向下扩展段达到最大长度。（打开向下扩展位会交换哪些字节可访问、哪些不可访问。）

向下扩展特性使通过把栈复制到更大的段来扩展栈成为可能，而无需同时更新栈内指针。

描述符表描述符的界限字段用于防止程序选择描述符表之外的表项。描述符表的界限标识表中最后一个描述符的最后一个有效字节。由于每个描述符长 8 字节，对于最多含 N 个描述符的表，界限值为 N×8−1。

界限检查能发现越界下标、非法指针计算等编程错误。这类错误在发生时即被检测到，因而更容易确定原因。没有界限检查时，这类错误可能破坏其他模块，直到被破坏的模块出现异常行为才被发现，那时很难定位原因。

| 情形 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|
| 扩展方向 | 向上 | 向上 | 向下 | 向下 |
| G 位 | 0 | 1 | 0 | 1 |
| B 位 | X | X | 0 | 1 |
| 下界 | 0 | 0 | LIMIT+1 | shl(LIMIT,12,1)+1 |
| 上界 | LIMIT | shl(LIMIT,12,1) | 64K−1 | 4G−1 |
| 最大段长 | 64K（0–FFFF） | 4G（0–FFFFFFFF） | 64K−1（!(0–0)） | 4G−4K（!(0–FFF)） |
| 最小段长 | 1（0–0） | 4K（0–FFF） | 0（!(0–FFFF)） | 0（!(0–FFFFFFFF)） |

`shl(X,12,1)` 表示把 X 左移 12 位，并在右侧插入 1。

### 6.3.1.3 特权级

特权概念通过给处理器识别的关键对象赋予 0 到 3 的值来实现。这个值称为**特权级（privilege level）**：0 表示最高特权，3 表示最低特权。处理器识别的以下对象含有特权级：

- 描述符含有**描述符特权级（DPL）**字段。
- 选择子含有**请求者特权级（RPL）**字段，RPL 用于表示产生该选择子的过程的特权级。
- 处理器内部寄存器记录**当前特权级（CPL）**。通常 CPL 等于处理器当前执行段的 DPL；当控制转移到 DPL 不同的段时，CPL 随之改变。

处理器通过比较 CPL 与一个或多个其他特权级，自动评估一个过程访问另一个段的权限。评估在选择子装入段寄存器时进行。访问数据的评估标准与控制转移到可执行段的标准不同，因此下面分别讨论。

图 6-2 把这些特权级解释为保护环。中心环包含最关键软件的段，通常是操作系统内核；外层环包含较不重要软件的段。

不必使用全部四个特权级。原本只使用一两个特权级的软件，可以忽略 80386 提供的其他级别。单级系统应使用特权级 0；两级系统应使用特权级 0 和 3。

## 6.3.2 限制对数据的访问

要在内存中寻址操作数，80386 程序必须把数据段的选择子装入数据段寄存器（DS、ES、FS、GS、SS）。处理器通过比较特权级自动评估对数据段的访问，评估在目标段描述符的选择子装入数据段寄存器时进行。如图 6-3 所示，这类特权检查涉及三个不同的特权级：

1. CPL（当前特权级）；
2. 用于指定目标段的选择子的 RPL（请求者特权级）；
3. 目标段描述符的 DPL。

只有当目标段的 DPL 在数值上大于或等于 CPL 与选择子 RPL 中的较大者时，指令才能装入数据段寄存器（并随后使用目标段）。换言之，过程只能访问同级或较低特权级的数据。

任务的可寻址范围随 CPL 改变。CPL 为 0 时，可访问所有特权级的数据段；CPL 为 1 时，只能访问特权级 1–3 的数据段；CPL 为 3 时，只能访问特权级 3 的数据段。例如，这一特性可防止应用程序读取或修改操作系统的表。

### 6.3.2.1 访问代码段中的数据

用代码段存放数据不如用数据段常见，但代码段可以合法地保存常量；被描述为代码段的段不能写入。访问代码段中的数据有以下方法：

1. 用非一致、可读、可执行段的选择子装入数据段寄存器；
2. 用一致、可读、可执行段的选择子装入数据段寄存器；
3. 使用 CS 超越前缀读取已装入 CS 寄存器的可读、可执行段。

第 1 种情况适用与数据段相同的规则。第 2 种情况总是有效，因为一致位置位的段，其特权级实际上等于 CPL，与 DPL 无关。第 3 种情况也总是有效，因为 CS 中代码段的 DPL 按定义等于 CPL。

## 6.3.3 限制控制转移

在 80386 中，控制转移由 `JMP`、`CALL`、`RET`、`INT`、`IRET` 指令以及异常和中断机制完成。异常和中断是特殊情况，第 9 章讨论；本章只讨论 `JMP`、`CALL` 和 `RET`。

`JMP`、`CALL`、`RET` 的“近”形式在当前代码段内转移，因此只受界限检查约束。处理器确保 `JMP`、`CALL` 或 `RET` 的目的地址不超过当前可执行段的界限。该界限缓存在 CS 寄存器中，因此近转移的保护检查不需要额外时钟周期。

`JMP` 和 `CALL` 的“远”形式，其操作数引用其他段，因此处理器执行特权检查。`JMP` 或 `CALL` 引用另一个段有两种方式：

1. 操作数选择另一个可执行段的描述符；
2. 操作数选择调用门描述符。这种经门转移的形式将在后面关于调用门的一节讨论。

如图 6-4 所示，对于不使用调用门的控制转移，特权检查涉及两个特权级：

1. CPL（当前特权级）；
2. 目标段描述符的 DPL。

通常 CPL 等于处理器当前执行段的 DPL；不过，若当前可执行段的描述符中一致位置位，CPL 可以大于 DPL。处理器在 CS 寄存器中缓存 CPL 的记录，该值可能与代码段描述符中的 DPL 不同。

只有当以下特权规则之一满足时，处理器才允许 `JMP` 或 `CALL` 直接转移到另一个段：

- 目标的 DPL 等于 CPL；
- 目标代码段描述符的一致位置位，且目标的 DPL 小于或等于 CPL。

描述符中一致位置位的可执行段称为**一致段（conforming segment）**。一致段机制允许共享那些可能从不同特权级调用、但应在调用者特权级执行的过程，例如数学库和某些异常处理程序。控制转移到一致段时，CPL 不变；这是 CPL 可能不等于当前可执行段 DPL 的唯一情况。

大多数代码段不是一致段。上述基本特权规则意味着：对于非一致段，不经门就只能把控制转移到同一特权级的可执行段。但确实需要把控制转移到（数值上）更小的特权级，这一需求由 `CALL` 配合调用门描述符来满足，下一节将解释。`JMP` 永远不能把控制转移到 DPL 不等于 CPL 的非一致段。

## 6.3.4 门描述符守护过程入口点

为了在不同特权级的可执行段之间提供受保护的控制转移，80386 使用门描述符。门描述符有四种：

- 调用门（Call gates）
- 陷阱门（Trap gates）
- 中断门（Interrupt gates）
- 任务门（Task gates）

本章只关心调用门。任务门用于任务切换，因此放在第 7 章讨论；第 9 章解释陷阱门和中断门如何用于异常和中断。图 6-5 说明了调用门的格式。调用门描述符可以位于 GDT 或 LDT 中，但不能位于 IDT 中。调用门有两个主要功能：

1. 定义过程的入口点；
2. 规定入口点的特权级。

调用指令和跳转指令使用调用门描述符的方式与使用代码段描述符相同。当硬件识别出目的选择子指向门描述符时，指令的操作会按调用门的内容展开。

门的**选择子**和**偏移**字段构成指向过程入口点的指针。调用门保证所有转移到另一个段的操作都进入有效入口点，而不会进入过程中间（更糟的是进入指令中间）。控制转移指令的远指针操作数并不指向目标指令的段和偏移；相反，指针的选择子部分选择一个门，偏移部分不使用。图 6-6 说明了这种寻址方式。

如图 6-7 所示，经调用门进行控制转移的有效性检查涉及四个特权级：

1. CPL（当前特权级）；
2. 用于指定调用门的选择子的 RPL；
3. 门描述符的 DPL；
4. 目标可执行段描述符的 DPL。

门描述符的 DPL 字段决定哪些特权级可以使用该门。一个代码段可以有多个过程，分别供不同特权级使用。例如，操作系统可能有一些供应用程序使用的服务，另一些只供其他系统软件使用。

门可用于转移到数值上更小的特权级，也可用于转移到同一特权级（尽管同级转移并不需要门）。只有 `CALL` 指令能用门转移到更小的特权级；`JMP` 指令用门只能转移到同一特权级的可执行段或一致段。

对于转移到非一致段的 `JMP`，必须同时满足以下两条特权规则，否则产生通用保护异常：

```
MAX(CPL, RPL) <= 门 DPL
目标段 DPL = CPL
```

对于 `CALL`（或转移到一致段的 `JMP`），必须同时满足以下两条规则，否则产生通用保护异常：

```
MAX(CPL, RPL) <= 门 DPL
目标段 DPL <= CPL
```

### 6.3.4.1 栈切换

如果调用门的目标代码段与 CPL 处于不同特权级，就请求了一次**跨级转移（interlevel transfer）**。

为维护系统完整性，每个特权级都有独立的栈。这些栈保证有足够空间处理来自较低特权级的调用；否则，若调用过程未在调用者栈上提供足够空间，受信任的过程就无法正常工作。

处理器通过任务状态段（TSS）定位这些栈（见图 6-8）。每个任务有独立的 TSS，因而可以有独立的栈。系统软件负责创建 TSS，并在其中放入正确的栈指针。TSS 中的初始栈指针严格是只读值，处理器在执行过程中从不改变它们。

使用调用门改变特权级时，处理器从 TSS 装入一个指针值来选择新栈，并用目标代码段的 DPL（即新 CPL）索引 PL 0、PL 1 或 PL 2 的初始栈指针。

新栈数据段的 DPL 必须等于新 CPL，否则发生栈异常。系统软件负责为所有用到的特权级创建栈和栈段描述符。每个栈必须有足够空间容纳旧 SS:ESP、返回地址，以及处理调用可能需要的全部参数和局部变量。

与同级调用一样，子程序参数放在栈上。为使特权转换对被调用过程透明，处理器把参数复制到新栈。调用门的**计数字段**告诉处理器从调用者栈复制多少个双字（最多 31 个）到新栈；计数为零则不复制参数。

执行跨级 `CALL` 时，处理器完成以下与栈有关的步骤：

1. 检查新栈是否足够大，能容纳参数和链接信息；若不够，发生栈错误，错误码为 0。
2. 把栈寄存器 SS:ESP 的旧值作为两个双字压入新栈。
3. 复制参数。
4. 把 `CALL` 之后那条指令的指针（原 CS:EIP 值）压入新栈。SS:ESP 的最终值指向新栈上的这个返回指针。

图 6-9 说明了成功跨级调用之后的栈内容。

TSS 中没有特权级 3 的栈指针，因为特权级 3 不能被任何其他特权级的过程调用。

可能被其他特权级调用、且需要超过 31 个双字参数的过程，必须使用保存的 SS:ESP 链接来访问最后一个被复制双字之后的所有参数。

经调用门的调用不检查复制到新栈上的字的值。被调用过程应检查每个参数的有效性。后面一节讨论如何用 `ARPL`、`VERR`、`VERW`、`LSL` 和 `LAR` 指令检查指针值。

### 6.3.4.2 从过程返回

`RET` 指令的“近”形式在当前代码段内转移控制，因此只受界限检查约束。它从栈上弹出对应 `CALL` 之后那条指令的偏移，处理器确保该偏移不超过当前可执行段的界限。

`RET` 指令的“远”形式弹出先前远 `CALL` 压入栈的返回指针。正常情况下，由于它与先前 `CALL` 或 `INT` 的关系，该指针是有效的。尽管如此，处理器仍执行特权检查，因为当前过程可能修改了指针，或未能正确维护栈。返回指令从栈上弹出的 CS 选择子的 RPL 标识调用过程的特权级。

段间返回指令可以改变特权级，但只能转向特权更低的（数值更大的）过程。当 `RET` 遇到的已保存 CS 值的 RPL 在数值上大于 CPL 时，发生跨级返回。此类返回按以下步骤进行：

1. 执行表 6-3 所示的检查，并用栈上保存的原值装入 CS:EIP 和 SS:ESP。
2. 按 `RET` 指令中指示的字节数调整旧的 SS:ESP（当前栈顶）值。得到的 ESP 不与栈段界限比较；若 ESP 越界，要到下一次栈操作才会被发现。（返回过程的 SS:ESP 值不被保留；正常情况下，该值与 TSS 中的值相同。）
3. 检查 DS、ES、FS、GS 段寄存器的内容。若其中任何寄存器引用的段，其 DPL 大于新 CPL（一致代码段除外），则把该段寄存器装入空选择子（INDEX=0，TI=0）。`RET` 指令本身在这些情况下不发出异常；但此后任何试图使用含空选择子的段寄存器的内存引用都会导致通用保护异常。这可以防止较低特权代码利用较高特权过程留在段寄存器中的选择子访问更高特权的段。

| 检查类型 | 异常 | 错误码 |
|---|---|---|
| ESP 在当前 SS 段内 | SF | 0 |
| ESP+7 在当前 SS 段内 | SF | 0 |
| 返回 CS 的 RPL 大于 CPL | GP | 返回 CS |
| 返回 CS 选择子非空 | GP | 返回 CS |
| 返回 CS 段在描述符表界限内 | GP | 返回 CS |
| 返回 CS 描述符是代码段 | GP | 返回 CS |
| 返回 CS 段存在 | NP | 返回 CS |
| 返回的非一致代码段 DPL = 返回 CS 的 RPL，或返回的一致代码段 DPL ≤ 返回 CS 的 RPL | GP | 返回 CS |
| ESP+N+15 在 SS 段内（N 为 `RET N` 的立即操作数） | SF | 返回 SS |
| ESP+N+12 处的 SS 选择子非空 | GP | 返回 SS |
| ESP+N+12 处的 SS 选择子在描述符表界限内 | GP | 返回 SS |
| SS 描述符是可写数据段 | GP | 返回 SS |
| SS 段存在 | SF | 返回 SS |
| 已保存 SS 段的 DPL = 已保存 CS 的 RPL | GP | 返回 SS |
| 已保存 SS 选择子的 RPL = 已保存 SS 段的 DPL | GP | 返回 SS |

SF = 栈错误，GP = 通用保护异常，NP = 段不存在异常。

## 6.3.5 部分指令保留给操作系统

有能力影响保护机制或影响整个系统性能的指令，只能由受信任的过程执行。80386 有两类这样的指令：

1. **特权指令**——用于系统控制的指令；
2. **敏感指令**——用于 I/O 及与 I/O 有关活动的指令。

### 6.3.5.1 特权指令

影响系统数据结构的指令只能在 CPL 为零时执行。若 CPL 大于零时 CPU 遇到这些指令，就发出通用保护异常。这些指令包括：

- `CLTS`——清除任务已切换标志
- `HLT`——停止处理器
- `LGDT`——装入 GDT 寄存器
- `LIDT`——装入 IDT 寄存器
- `LLDT`——装入 LDT 寄存器
- `LMSW`——装入机器状态字
- `LTR`——装入任务寄存器
- `MOV` 到/从 CRn——与控制寄存器 n 之间传送
- `MOV` 到/从 DRn——与调试寄存器 n 之间传送
- `MOV` 到/从 TRn——与测试寄存器 n 之间传送

### 6.3.5.2 敏感指令

处理 I/O 的指令需要受限，但也需要由非零特权级的过程执行。I/O 操作限制机制详见第 8 章“输入/输出”。

## 6.3.6 指针验证指令

指针验证是定位编程错误的重要环节，也是维持特权级隔离所必需的。指针验证包括以下步骤：

1. 检查指针的提供者是否有权访问该段；
2. 检查段类型是否适合其预期用途；
3. 检查指针是否违反段界限。

虽然 80386 处理器在执行指令期间自动完成第 2、3 步检查，但第 1 步需要软件协助。非特权指令 `ARPL` 就是为此提供的。软件也可以显式执行第 2、3 步来检查潜在违规（而不是等待异常），为此提供了非特权指令 `LAR`、`LSL`、`VERR` 和 `VERW`。

`LAR`（装入访问权）用于验证指针引用的段具有适当的特权级和类型。`LAR` 有一个操作数，即待检查描述符的选择子。该描述符必须在 CPL 与选择子 RPL 的较大者所对应的特权级上可见。若可见，`LAR` 取得描述符第二个双字的掩码形式，用 00FxFF00H 掩码，把结果存入指定的 32 位目的寄存器并置位零标志。（x 表示所存值中相应的 4 位未定义。）装入之后即可测试访问权位。`LAR` 可以测试所有有效的描述符类型。若 RPL 或 CPL 大于 DPL，或选择子超出表界限，则不返回访问权值，并清零零标志。一致代码段可以从任何特权级访问。

`LSL`（装入段界限）允许软件测试描述符的界限。若给定选择子（在内存或寄存器中）所指的描述符在 CPL 可见，`LSL` 就把由碎片化的界限字段和描述符 G 位计算出的 32 位、字节粒度、已还原的界限装入指定的 32 位寄存器。此操作只适用于段（数据段、代码段、任务状态段和局部描述符表）；门描述符不可访问（表 6-4 详细列出了哪些类型有效、哪些无效）。界限的解释取决于段类型，例如向下扩展数据段对界限的处理与代码段不同。对 `LAR` 和 `LSL`，若装入成功则置位零标志 ZF，否则清零 ZF。

|---|---|---|
| 0 | （无效） | 否 |
| 1 | 可用的 286 TSS | 是 |
| 2 | LDT | 是 |
| 3 | 忙的 286 TSS | 是 |
| 4 | 286 调用门 | 否 |
| 5 | 任务门 | 否 |
| 6 | 286 陷阱门 | 否 |
| 7 | 286 中断门 | 否 |
| 8 | （无效） | 否 |
| 9 | 可用的 386 TSS | 是 |
| A | （无效） | 否 |
| B | 忙的 386 TSS | 是 |
| C | 386 调用门 | 否 |
| D | （无效） | 否 |
| E | 386 陷阱门 | 否 |
| F | 386 中断门 | 否 |

### 6.3.6.1 描述符验证

80386 有两条指令 `VERR` 和 `VERW`，用于判断选择子所指的段在当前特权级能否读取或写入。即使结果为否，这两条指令也不会引发保护错误。

`VERR`（验证可读）验证段是否可读，若该段可从当前特权级读取，则把 ZF 置 1。`VERR` 检查：

- 选择子指向 GDT 或 LDT 界限内的描述符；
- 该描述符是代码段或数据段描述符；
- 段可读且特权级适当。

对数据段和非一致代码段的特权检查要求 DPL 在数值上大于或等于 CPL 与选择子 RPL 两者。一致段不检查特权级。

`VERW`（验证可写）提供与 `VERR` 相同的可写性验证能力。与 `VERR` 一样，若可写性检查结果为正，`VERW` 置位 ZF。该指令检查描述符在界限内、是段描述符、可写，且其 DPL 在数值上大于或等于 CPL 与选择子 RPL 两者。代码段无论是否一致，永远不可写。

### 6.3.6.2 指针完整性与 RPL

请求者特权级（RPL）特性可以防止指针的不当使用，以免较低特权级破坏更高特权代码或数据的运行。

常见例子是文件系统过程 `FREAD(file_id, n_bytes, buffer_ptr)`。这个假想过程把文件数据读入缓冲区，覆盖原有内容。正常情况下，`FREAD` 在用户级可用，只向位于特权级并运行于特权级的文件系统过程和数据提供指针；这样的过程通常能阻止用户级过程直接修改文件表。然而，若没有检查指针有效性的标准协议，用户级过程就可以用一个指向文件表的指针代替缓冲区指针，使 `FREAD` 在不知情的情况下破坏文件表。

使用 RPL 可以避免这类问题。RPL 字段允许给选择子赋予一个特权属性，通常表示生成该选择子的代码的特权级。80386 处理器自动检查装入段寄存器的任何选择子的 RPL，以决定 RPL 是否允许访问。

为了利用处理器的 RPL 检查，被调用过程只需确保传给它的所有选择子，其 RPL 至少与原始调用者的 CPL 一样高（数值上不小于）。这一动作保证选择子不会比其提供者更受信任。若其中某个选择子被用来访问调用者本来无法直接访问的段，即 RPL 在数值上大于 DPL，那么该选择子装入段寄存器时就会产生保护错误。

`ARPL`（调整请求者特权级）把选择子的 RPL 字段调整为原值与指定寄存器中 RPL 字段值中的较大者。后者通常从栈上调用者 CS 寄存器的映像装入。若调整改变了选择子的 RPL，则置位零标志 ZF，否则清零 ZF。
