# 7.6 任务链接

TSS 的回链（back-link）字段与标志字中的 NT（嵌套任务）位共同作用，使 80386 能自动返回到调用另一个任务、或被另一个任务中断的任务。当 `CALL` 指令、中断指令、外部中断或异常引发切换到新任务时，80386 自动用即将离开任务的 TSS 选择子填入新 TSS 的回链字段，同时置位新任务标志寄存器中的 NT 位。NT 标志指示回链字段是否有效。新任务通过执行 `IRET` 指令释放控制权。解释 `IRET` 时，80386 检查 NT 标志：若 NT 置位，则切换回回链字段所选的任务。表 7-2 汇总了这些字段的用途。

| 受影响字段 | `JMP` 指令的效果 | `CALL` 指令的效果 | `IRET` 指令的效果 |
|---|---|---|---|
| 新任务的忙位 | 置位，之前必须为 0 | 置位，之前必须为 0 | 不变，必须已置位 |
| 原任务的忙位 | 清零 | 不变（已置位） | 清零 |
| 新任务的 NT 位 | 清零 | 置位 | 不变 |
| 原任务的 NT 位 | 不变 | 不变 | 清零 |
| 新任务的回链 | 不变 | 置为原任务 TSS 选择子 | 不变 |
| 原任务的回链 | 不变 | 不变 | 不变 |

## 7.6.1 忙位防止循环

TSS 描述符的 B 位（忙位）保证回链的完整性。当中断任务中断其他中断任务，或被调用任务调用其他任务时，回链可以增长到任意长度。忙位确保 CPU 能检测任何形成循环的企图。循环意味着试图重入一个已经忙的任务，而 TSS 不是可重入资源。

处理器按如下方式使用忙位：

1. 切换到某任务时，处理器自动置位新任务的忙位。
2. 从某任务切出时，若该任务不放入回链（即引发切换的指令是 `JMP` 或 `IRET`），处理器自动清零原任务的忙位；若该任务放入回链，则其忙位置位不变。
3. 切换到某任务时，若新任务的忙位已置位，处理器发出异常。

通过这些动作，处理器防止任务切换到自身，或切换到回链上的任何任务，从而防止非法重入任务。

忙位在多处理器配置中同样有效，因为处理器在置位或清零忙位时自动断言总线锁。这确保两个处理器不会同时调用同一个任务（多处理的更多内容见第 11 章）。

## 7.6.2 修改任务链接

任何对任务链接顺序的修改，都只能由可以信任其正确更新回链和忙位的软件完成。若需要在中断它的任务之前恢复某个被中断任务，就可能需要这种修改。把任务从回链中移除的受信任软件必须遵循以下策略之一：

1. 先修改中断任务 TSS 中的回链字段，再清零被移除任务 TSS 描述符中的忙位；
2. 确保在更新回链与忙位之间不发生中断。
