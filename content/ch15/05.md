# 15.5 虚拟 I/O

许多为单任务系统设计的 8086 程序直接使用 I/O 设备。然而，这些程序在多任务环境中执行时，这种设备使用方式可能造成破坏。80386 提供了足够的灵活性，可以按既适合新环境、又对 8086 程序透明的方式控制 I/O。设计者可以采用以下几种可能的方法之一：

- 把 8086 操作系统实现或模拟为 80386 程序，要求 8086 应用通过软件中断调用操作系统来完成 I/O，并捕获所有直接 I/O 的企图；
- 让 8086 程序完全控制所有 I/O；
- 有选择地捕获并模拟任务对特定 I/O 端口的引用；
- 捕获或重定向对内存映射 I/O 地址的引用。

控制 I/O 的方法取决于 I/O 端口是 I/O 映射还是内存映射。

## 15.5.1 I/O 映射的 I/O

V86 模式下的 I/O 映射 I/O 与保护模式的唯一区别是：执行 `IN`、`INS`、`OUT`、`OUTS` 指令时，保护机制不查询 IOPL。只有 I/O 许可位图控制 V86 任务执行这些 I/O 指令的权利。

I/O 许可位图根据 I/O 指令引用的 I/O 地址有选择地捕获它们。每个 V86 任务的 I/O 许可位图决定该任务哪些 I/O 地址被捕获。由于每个任务可以有不同的位图，为一个任务捕获的地址可能不同于为其他任务捕获的地址。I/O 许可位图的更多信息见第 8 章。

## 15.5.2 内存映射 I/O

在使用内存映射 I/O 的硬件设计中，可以利用 80386 的分页设施捕获或重定向 I/O 操作。每个执行内存映射 I/O 的任务，必须为内存映射地址空间分配一页（或多页）。V86 监视器可以通过以下任一方式控制内存映射 I/O：

- 把内存映射页分配到适当的物理地址。不同任务可以有不同的物理地址，从而防止任务相互干扰。
- 通过强制内存映射页产生页错误，使控制陷入监视器。只读页捕获写操作；不存在的页同时捕获读和写。

对某些 I/O 设备而言，每次 I/O 都介入可能过于频繁。此时仍可以用页错误在第一次 I/O 操作时介入；监视器至少可以确保任务独占该设备，然后把页状态改为存在且可读写，让后续 I/O 全速进行。

## 15.5.3 特殊 I/O 缓冲区

智能控制器的缓冲区（例如位图图形缓冲区）也可以通过页映射虚拟化。缓冲区的线性空间可以为每个虚拟 8086 任务映射到不同的物理空间；V86 监视器随后可以负责假脱机数据，或在适当时刻把虚拟缓冲区分配给真实缓冲区。
