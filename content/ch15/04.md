# 15.4 额外的敏感指令

80386 在 V86 模式下执行时，`PUSHF`、`POPF`、`INT n` 和 `IRET` 指令对 IOPL 敏感。`IN`、`INS`、`OUT`、`OUTS` 在保护模式中通常敏感，但在 V86 模式中不敏感。以下是 V86 模式下敏感指令的完整列表：

- `CLI`——清中断允许标志
- `STI`——置中断允许标志
- `LOCK`——断言总线锁信号
- `PUSHF`——压入标志
- `POPF`——弹出标志
- `INT n`——软件中断
- `IRET`——中断返回

V86 模式下 CPL 总是 3，因此若 IOPL < 3，这些指令将触发通用保护异常。使这些指令敏感，是为了让 V86 监视器能模拟它们的功能。

## 15.4.1 模拟 8086 操作系统调用

`INT n` 之所以敏感，是为了让 V86 监视器能拦截对 8086 OS 的调用。许多 8086 操作系统通过把参数压栈、再执行 `INT n` 来调用。若 IOPL < 3，`INT n` 会被 V86 监视器拦截；监视器随后可以模拟 8086 操作系统的功能，或把中断反射回 V86 模式中的 8086 操作系统。

## 15.4.2 虚拟化中断允许标志

处理器在 V86 任务中执行 8086 代码时，`PUSHF`、`POPF` 和 `IRET` 对 IOPL 敏感，以便 V86 监视器控制中断允许标志 IF 的改变。其他影响 IF 的指令（`STI`、`CLI`）在 8086 代码和 80386 代码中都对 IOPL 敏感。

许多为单任务系统设计的 8086 程序通过设置和清除 IF 控制中断。然而，这些程序在多任务环境中执行时，这种对 IF 的控制可能造成破坏。若 IOPL 小于 3，所有改变或查询 IF 的指令都会陷入 V86 监视器；监视器随后可以按既适合大环境、又对 8086 程序透明的方式控制 IF。
