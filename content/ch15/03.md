# 15.3 进入与离开 V86 模式

图 15-2 汇总了处理器进入和离开 8086 程序的方式。处理器可以通过两种方式进入 V86 模式：

1. **任务切换**到某个 80386 任务时，从新 TSS 装入 EFLAGS 映像。新任务的 TSS 必须是 80386 TSS，不能是 80286 TSS，因为 80286 TSS 不保存 EFLAGS 的高位字（其中含有 VM 标志）。新 EFLAGS 的 VM 位为 1 表示新任务执行 8086 指令；因此，在从 TSS 装入段寄存器时，处理器按 8086 方式形成基地址。
2. **从 80386 任务的过程执行 `IRET`** 时，从栈装入 EFLAGS 映像。此时 VM 为 1 表示控制要返回的过程是 8086 过程。执行 `IRET` 时的 CPL 必须为零，否则处理器不改变 VM。

处理器在发生中断或异常时离开 V86 模式，分两种情况：

1. **中断或异常引发任务切换**。从 V86 任务切换到任何其他任务时，从新任务 TSS 装入 EFLAGS。若新 TSS 是 80386 TSS 且 EFLAGS 映像中的 VM 位为零，或新 TSS 是 80286 TSS，处理器就清除 EFLAGS 的 VM 位，使用 80386 风格地址形成从新 TSS 装入段寄存器，并按 80386 保护模式语义开始执行新任务的指令。
2. **中断或异常向量指向特权级 0 的过程**。处理器把 EFLAGS 的当前设置存入栈，然后清除 VM 位；因此，中断或异常处理程序作为“原生”80386 保护模式代码执行。若中断或异常向量指向一致段或非 3 的特权级，处理器产生通用保护异常，错误码是试图转移到的可执行段的选择子。

系统软件不直接操作 VM 标志，而是操作存放在栈上或 TSS 中的 EFLAGS 寄存器映像。V86 监视器在首次创建 V86 任务时，设置栈上或 TSS 中 EFLAGS 映像的 VM 标志。异常和中断处理程序可以检查栈上的 VM 标志；若被中断的过程在 V86 模式下执行，处理程序可能需要调用 V86 监视器。

## 15.3.1 通过任务切换的转换

切换到 V86 任务或从 V86 任务切出，可能由以下三种原因之一引起：

1. 向量指向任务门的中断；
2. 80386 操作系统调度器的动作；
3. NT 标志置位时的 `IRET`。

在这些情况下，处理器根据新 TSS 中的 EFLAGS 映像改变 EFLAGS 的 VM 位。若新 TSS 是 80286 TSS，其中没有 EFLAGS 高位字，处理器清除 VM。处理器在从新 TSS 映像装入段寄存器之前更新 VM；VM 的新设置决定处理器把新的段寄存器映像解释为 8086 选择子还是 80386/80286 选择子。

## 15.3.2 通过陷阱门和中断门的转换

处理器因异常或中断经陷阱门或中断门向量到特权级 0 过程而离开 V86 模式。异常或中断处理程序通过执行 `IRET` 返回 8086 代码。

由于 8086 程序是为 8086 处理器执行而设计的，V86 任务中的 8086 程序会有从线性地址零开始的 8086 风格中断表。不过，80386 不直接使用该表；对于 V86 模式中发生的所有异常和中断，处理器都通过 IDT 向量。V86 任务中发生的中断或异常，其 IDT 表项必须含有：

- 任务门；或
- 80386 陷阱门（类型 14）或 80386 中断门（类型 15），且必须指向非一致、特权级 0 的代码段。

IDT 中具有 80386 陷阱门或中断门的中断和异常，向量到特权级 0 的相应处理过程。所有 8086 段寄存器的内容都保存在 PL 0 栈上。图 15-3 给出了 V86 任务执行 8086 程序时发生异常或中断后 PL 0 栈的格式。

处理器把所有 8086 段寄存器存入 PL 0 栈之后，在开始执行处理过程之前把所有段寄存器装入零。这使中断处理程序能安全地把 DS、ES、FS、GS 作为 80386 选择子保存和恢复。无论在普通任务还是 V86 任务的上下文中被调用，中断处理程序都可以使用相同的寄存器保存/恢复序言和收尾代码。执行 `IRET` 之前把零恢复到这些寄存器不会在处理程序中引发陷阱。期望段寄存器中有值、或通过段寄存器返回值的打断过程，必须使用保存在 PL 0 栈上的寄存器映像。需要知道中断是否发生在 V86 模式的处理程序，可以检查所存 EFLAGS 映像中的 VM 位。

若栈上保存的 EFLAGS 映像中 VM 位置位，且该中断或异常是监视器需要处理的，中断处理程序就把控制传给 V86 监视器。V86 监视器可以：

- 完全在 V86 监视器内处理该中断；
- 调用 8086 程序的中断处理程序。

把中断或异常反射回 8086 代码包括以下步骤：

1. 查阅 8086 中断向量，定位相应的处理过程；
2. 把 8086 程序的状态存入特权级 3 栈；
3. 修改 PL 0 栈上的返回链接，使其指向特权级 3 处理过程；
4. 执行 `IRET`，把控制传给该处理程序；
5. 当特权级 3 处理程序的 `IRET` 再次陷入 V86 监视器时，恢复 PL 0 栈上的返回链接，使其指向最初被中断的特权级 3 过程；
6. 执行 `IRET`，把控制返回被中断的过程。
