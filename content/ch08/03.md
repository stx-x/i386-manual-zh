# 8.3 保护与 I/O

有两种机制为 I/O 功能提供保护：

1. EFLAGS 寄存器中的 IOPL 字段定义使用 I/O 相关指令的权利；
2. 80386 TSS 段中的 I/O 许可位图定义使用 I/O 地址空间中端口的权利。

这些机制只在保护模式下（包括虚拟 8086 模式）起作用，在实模式下不起作用。实模式没有 I/O 空间保护：任何过程都可以执行 I/O 指令，任何 I/O 端口都可以被 I/O 指令寻址。

## 8.3.1 I/O 特权级

I/O 指令必须受限，却又不能只让特权级 0 的过程执行。为此，处理器用标志寄存器的两个位存放 **I/O 特权级（IOPL）**。IOPL 定义执行 I/O 相关指令所需的特权级。

只有满足 CPL ≤ IOPL 时，才能执行以下指令：

- `IN`——输入
- `INS`——输入串
- `OUT`——输出
- `OUTS`——输出串
- `CLI`——清中断允许标志
- `STI`——置中断允许标志

这些指令称为“敏感”指令，因为它们对 IOPL 敏感。

要使用敏感指令，过程必须在至少与 IOPL 规定的特权级一样高的级别执行（CPL ≤ IOPL）。较低特权过程试图使用敏感指令会导致通用保护异常。

由于每个任务都有自己独有的标志寄存器副本，每个任务可以有不同的 IOPL。主要执行 I/O 的任务（设备驱动程序）可以把 IOPL 设为 3，从而允许该任务的所有过程执行 I/O；其他任务通常把 IOPL 设为 0 或 1，把执行 I/O 指令的权利保留给特权最高的过程。

任务只能用 `POPF` 指令改变 IOPL，而且这种改变是特权的：除非过程在特权级 0 执行，否则不能改变 IOPL。较低特权过程试图改变 IOPL 不会导致异常，IOPL 只是保持不变。

除 `CLI` 和 `STI` 外，也可以用 `POPF` 改变中断允许标志 IF；不过，用 `POPF` 改变 IF 对 IOPL 敏感。过程只有在至少与 IOPL 一样高的特权级执行时，才能用 `POPF` 改变 IF。较低特权过程以这种方式改变 IF 不会导致异常，IF 只是保持不变。

## 8.3.2 I/O 许可位图

直接引用处理器 I/O 空间地址的 I/O 指令是 `IN`、`INS`、`OUT`、`OUTS`。80386 能有选择地捕获对特定 I/O 地址的引用。实现选择性捕获的结构是 TSS 段中的 **I/O 许可位图**（见图 8-2）。I/O 许可位图是一个位向量，其大小和在 TSS 段中的位置都是可变的。处理器通过 TSS 固定部分中的 I/O 映射基址字段定位该位图。I/O 映射基址字段宽 16 位，含有 I/O 许可位图起点的偏移。I/O 许可位图的上限与 TSS 段的界限相同。

在保护模式下遇到 I/O 指令（`IN`、`INS`、`OUT`、`OUTS`）时，处理器先检查 CPL ≤ IOPL 是否成立。若成立，I/O 操作可以继续；若不成立，处理器检查 I/O 许可位图。（在虚拟 8086 模式下，处理器不考虑 IOPL 而直接查询位图，见第 15 章。）

位图中的每一位对应一个 I/O 端口字节地址。例如，端口 41 的位位于 I/O 映射基址 + 5 的位偏移 1 处。处理器测试 I/O 操作所跨越的所有 I/O 地址对应的位；例如，双字操作测试四个相邻字节地址对应的四位。若任一被测位为 1，处理器发出通用保护异常；若所有被测位均为 0，I/O 操作可以继续。

I/O 许可位图不必表示所有 I/O 地址。位图未覆盖的 I/O 地址按位图中对应位为 1 处理。例如，若 TSS 界限等于 I/O 映射基址 + 31，则前 256 个 I/O 端口被映射；对编号大于 255 的任何端口执行 I/O 操作都会导致异常。

若 I/O 映射基址大于或等于 TSS 界限，该 TSS 段就没有 I/O 许可位图；当 CPL > IOPL 时，80386 程序中的所有 I/O 指令都会导致异常。

由于 I/O 许可位图位于 TSS 段中，不同任务可以有不同的位图。因此，操作系统可以通过修改任务 TSS 中的 I/O 许可位图，把端口分配给该任务。
