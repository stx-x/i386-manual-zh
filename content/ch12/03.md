# 12.3 调试异常

80386 有两个中断向量保留给与调试有关的异常。中断 1 是调用专为 80386 设计的调试器的主要手段；中断 3 用于调试调试器，以及与 Intel 8086 系列早期处理器兼容。

## 12.3.1 中断 1——调试异常

该异常的处理程序通常是调试器或调试系统的一部分。处理器在若干条件下引发中断 1。调试器可以检查 DR6 和 DR7 中的标志，判断是哪个条件导致异常，以及同时可能有哪些其他条件。表 12-2 给出了每个断点条件与指示该条件导致调试异常的位组合。

指令地址断点条件是故障，其他调试条件是陷阱。调试异常可以同时报告其中之一或两者。以下段落详细说明每一类调试异常。

| 要测试的标志 | 条件 |
|---|---|
| BS=1 | 单步陷阱 |
| B0=1 且 (GE0=1 或 LE0=1) | 断点 DR0、LEN0、R/W0 |
| B1=1 且 (GE1=1 或 LE1=1) | 断点 DR1、LEN1、R/W1 |
| B2=1 且 (GE2=1 或 LE2=1) | 断点 DR2、LEN2、R/W2 |
| B3=1 且 (GE3=1 或 LE3=1) | 断点 DR3、LEN3、R/W3 |
| BD=1 | 调试寄存器不可用；正被 ICE-386 使用 |
| BT=1 | 任务切换 |

### 12.3.1.1 指令地址断点

处理器在执行从给定地址开始的指令之前报告指令地址断点；因此，指令地址断点异常是故障。

RF（恢复标志）使调试处理程序能重试除调试故障之外还会导致其他故障的指令。检测到故障时，处理器自动在压栈的标志映像中置位 RF（但对陷阱和中止不置位 RF）。

RF 置位时，下一条指令执行期间将忽略任何调试故障（但 RF 不会使断点陷阱或其他类型的故障被忽略）。

处理器在每条指令成功完成时自动清除 RF，但 `IRET`、`POPF` 之后，以及导致任务切换的 `JMP`、`CALL`、`INT` 之后除外；这些指令按 EFLAGS 寄存器内存映像中的值设置 RF。

在进入任何故障处理程序之前，处理器自动在栈上的 EFLAGS 映像中置位 RF。例如，进入指令地址断点的故障处理程序时，栈上 EFLAGS 映像中的 RF 已置位；因此，处理程序末尾的 `IRET` 指令会在 EFLAGS 寄存器中置位 RF，执行将从断点地址恢复，而不会在同一地址再次产生断点故障。

若调试故障之后 RF 置位，且调试处理程序重试出错指令，重试可能引发其他故障。这些故障之后再次重试指令时仍会带着 RF=1，结果是调试故障继续被忽略。只有在指令成功完成后，处理器才清除 RF。

实模式调试器可以用 32 位 `IRET` 控制 RF 标志。16 位 `IRET` 不影响 RF 位（RF 位于 EFLAGS 的高 16 位）。要使用 32 位 `IRET`，调试器必须重新安排栈，使其含有适当的 32 位 EIP、CS 和 EFLAGS 值（EFLAGS 映像中 RF 置位）；然后执行带操作数大小前缀的 `IRET`，完成 32 位返回，把 RF 弹入 EFLAGS。

### 12.3.1.2 数据地址断点

数据地址断点异常是陷阱，即处理器在访问给定内存项的指令执行之后报告数据地址断点。

使用数据断点时，建议同时置位 DR7 的 LE 或 GE 位。若 LE 或 GE 置位，任何数据断点陷阱都会在访问指定内存项的指令完成之后准确报告。这种精确报告是通过强制 80386 执行单元在开始执行下一条指令之前等待数据操作数传送完成来实现的。若 GE 和 LE 都未置位，数据断点可能要到访问数据之后的一条指令才报告，甚至根本不报告。这是因为通常情况下，指令执行与内存传送高度重叠，前一条指令的内存传送尚未完成，下一条指令可能已经开始执行。

若调试器需要保留写断点位置的内容，应在设置写断点之前保存原内容。由于数据断点是陷阱，对断点位置的写入会在陷阱条件报告之前完成。处理程序可以在断点触发后报告保存的值；调试寄存器中的数据可用来定位触发断点的指令所存入的新值。

### 12.3.1.3 通用检测故障

当有人试图在 ICE-386 正在使用调试寄存器时使用它们，发生该异常。这一附加保护特性保证 ICE-386 在需要时能完全控制调试寄存器资源。ICE-386 使用调试寄存器，因此，使用这些寄存器的软件调试器不能在 ICE-386 使用时运行。异常处理程序可以检查 DR6 的 BD 位来判断这种情况。

### 12.3.1.4 单步陷阱

若指令开始时标志寄存器的陷阱标志 TF 为 1，则在该指令结束时发生此调试条件。注意，设置 TF 的指令结束时不会发生异常。例如，若用 `POPF` 设置 TF，则单步陷阱要到 `POPF` 之后的那条指令执行后才发生。

处理器在调用处理程序之前清除 TF 位。若任务切换时 TSS 标志映像中的 TF=1，则在新任务执行第一条指令之后发生异常。

单步标志通常不会因任务内的特权级改变而被清除。不过，`INT` 指令会清除 TF。因此，单步执行代码的软件调试器必须识别并模拟 `INT n` 或 `INTO`，而不是直接执行它们。

为维持保护，系统软件应在任何单步中断之后检查当前执行特权级，判断是否应在当前特权级继续单步执行。

硬件中断优先级保证：若发生外部中断，单步执行停止。当外部中断与单步中断同时发生时，先处理单步中断，这会清除 TF 位。保存返回地址或切换任务之后，在单步处理程序第一条指令执行之前检查外部中断输入；若外部中断仍待处理，则为其服务。外部中断处理程序不会被单步执行。要对中断处理程序单步执行，只需单步执行一条引用该处理程序的 `INT n` 指令。

### 12.3.1.5 任务切换断点

若新 TSS 的 T 位置位，则切换到 80386 任务之后也会发生调试异常。异常发生在控制已转给新任务、但新任务第一条指令尚未执行之时。处理程序可以检查调试状态寄存器 DR6 的 BT 位来判断这种情况。

注意，若调试异常处理程序本身是一个任务，其 TSS 的 T 位不应置位；否则处理器将进入无限循环。

## 12.3.2 中断 3——断点异常

该异常由执行断点指令 `INT 3` 引起。通常，调试器把单字节断点指令的操作码替换到待捕获指令的第一个操作码字节处，以此设置断点。`INT 3` 指令导致异常处理程序被调用时，保存的 CS:EIP 值指向 `INT 3` 之后的字节。

在早期处理器中，该特性被广泛用于捕获特定指令的执行。在 80386 上，过去由该特性满足的需求可以更方便地通过调试寄存器和中断 1 解决。不过，断点异常对于调试调试器仍然有用，因为它可以向量到与调试器所用不同的异常处理程序。当需要设置的断点数量超过调试寄存器允许的数量时，断点异常也很有用。
